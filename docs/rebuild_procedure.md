# 执行流程（从第1周到第8周）

## 每周通用步骤

1. 复制本周冻结配置到新目录；记录日期、Git/文件版本、ROS 发行版、仿真 seed、仿真/实车来源和变更理由。
2. 动手前写预注册：成功/失败判据、样本独立性、重复次数、超时预算、指标公式。冻结后只允许追加变更记录，不能覆盖原定义。
3. 先做离线或仿真基线，再做本周干预；每轮保存输入、原始输出、日志和配置快照。异常结果也保留。
4. 先复算原始数据，再填周验收表；未满足证据条件时标“未通过/待补”，不以“应该正常”推断。
5. 验收状态按周独立保留；工程联调可以在明确替代输入下前进，但后周结果不能反向填补前周缺项。第7周40次真实采样已冻结保存，复算不重复付费调用。

## 第1–4周：ROS、定位、导航

- W1：系统及仿真ROS graph已实际采集：odom/scan约10Hz，imu缺失，TF链有记录。硬件契约仍按真实缺项保留；详见项目根目录的最新结果报告。
- W2：静态仿真按课程的直行/转向序列重复3次，从 simulator truth 读仿真终点；小车物理基线单列，等末段安全检查后测。
- W3：用相同 seed 的真值图和 SLAM 图对比；定位误差样本必须来自新鲜估计消息，并用独立 simulator truth 比较。采样器检测 stale message 后跳过并记录。
- W4：运行三目标导航与巡航，两轮配置一致；`navigate_to` 使用60秒课程预算。超时路径必须先 cancel 并确认停止；无法确认时返回失败证据，不谎报已停。

## 第5–8周：感知、语义地图、LLM、审计

- W5：建立带标注真值的固定图像集，逐图逐阈值保存计数；小车已确认没有摄像头，使用已冻结20张公开室内场景；不再安排ESP32相机接入。
- W6：每个语义点有唯一 label、位置、last_seen；τ 表记录来源与单位。当前使用受控ROS合成检测验证age/state与Marker；三类τ来自标明合成的移动日志，真实场地τ另记未验证。运行方法见逐周第6周。
- W7：定义课程五工具：`navigate_to`、`get_semantic_map`、`capture_and_describe`、`say`、`stop`。先用 fixtures 完成 schema/拒绝校验；冻结后用 DeepSeek 做两条指令、温度0.2/0.8、各10次，原样保留40行日志。API 环境缺失或调用失败时停止该环节，不伪造结果。
- W8：加载第3周地图/costmap、第6周语义地图/τ、第7周 Schema 和第2/4周资源/导航预算。先跑正反8用例和第7周6条指令回归。然后固定每个陷阱的同一份原始模型输出，在 auditor off/on 两边分别记录结果；off 只允许干跑。最后通过 `/navigate_to` 执行一个可达命名点，记录 plan/audit/exec/report 和三段式汇报。

## 末段 ESP32 小车检查

先确认车轮悬空/场地清空、急停或电源切断方式可用、速度限制最低，再查当前固件真实话题。逐项检查 micro-ROS agent 连接、短时低速 `/cmd_vel`、零速停止，以及固件确实发布时的 `/odom`、`/imu`。小车没有摄像头。任何实际动作都单独留档；不向小车发送 Plan Auditor off 的结果。当前计划不会宣称已完成此环节。

当前交付、来源和下一实验见 [前八周交付清单](前八周交付清单.md)。V3仿真执行需显式传入 `--task-contracts config/task_contracts_v3.json`；历史V2录像和原40回答保持原样。
